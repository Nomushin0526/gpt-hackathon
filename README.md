# 相模原キャンパス イベント掲示板

北里大学 相模原キャンパスで行われるイベントを一覧化する Web アプリケーションです。

## 目的

1. **紙媒体でしか告知されていないイベントを学生に届ける**
   学生課が掲示板のポスターを写真ごと登録でき、学生はスマートフォンから一覧・検索できます。
2. **学生・団体が企画したイベントを学生課へ気軽に応募できるプラットフォームにする**
   学生個人や部活動・サークルがフォームから掲載を申請し、学生課が審査して公開します。

## 主な機能

### 学生向け
| 画面 | URL | 内容 |
| --- | --- | --- |
| イベント一覧 | `/` | キーワード・カテゴリ・主催者種別・期間(これから / 1週間以内 / 1か月以内 / 終了)で絞り込み。「要申込」「満員」バッジ、定員と申込人数を表示 |
| イベント詳細 | `/events/<id>` | 日時・場所(Google マップを埋め込み表示)・ポスター画像、参加申込フォーム。`.ics` でスマホのカレンダーに追加 |
| イベント応募 | `/submit` | 学生・団体がイベントを申請。送信すると **受付番号** が発行される |
| 審査状況 | `/status` | 受付番号で「審査待ち / 公開中 / 差し戻し」と学生課からのコメントを確認 |
| おすすめ | `/recommendations` | 閲覧履歴とお気に入りから、内容の近い開催前のイベントを表示(トップページにも 3 件表示) |
| お気に入り | `/favorites` | 詳細ページの「☆ お気に入りに保存」で保存したイベントの一覧 |

### 学生課向け(`/admin`、Google または共通パスワードでログイン)
- 審査待ち・公開中・差し戻しのタブで応募を管理
- 応募内容と非公開の連絡事項を確認し、**承認して公開** / **コメント付きで差し戻し**
- 紙の掲示物などを学生課が直接登録(審査なしで即公開)
- イベントの編集・ポスター差し替え・削除
- イベントのデータ分析(`/admin/analytics`): 申込数・閲覧数・お気に入り数・定員充足率をカテゴリ別・曜日別・イベント別に集計。CSV でも保存可能

一覧では「学生課掲載」と「学生企画」がバッジで区別されます。

### 参加方法と申込人数
イベント登録時に参加方法を次の 3 つから選びます。

| 参加方法 | 一覧の表示 | 説明 |
| --- | --- | --- |
| 申込不要(当日参加自由) | 申込不要 | 定員を入れた場合は定員のみ表示 |
| このサイトで参加申込を受け付ける | ✍ 要申込 / 満員 | 申込人数と残り人数を表示。10 秒ごとに自動更新され、定員に達すると自動で締め切る |
| 外部フォーム・窓口などで申込 | ✍ 要申込 | 申込方法・申込先(Google フォームの URL など)の入力が必須 |

サイトで受け付けた申込者は、学生課の管理画面で一覧表示・CSV ダウンロード・取消ができます。

### 開催場所と地図
- **入力**: 開催場所の欄に名称を入れると候補が表示されます。学内の建物(L1号館、北里大学中央図書館、総合体育館など)は先頭に、
  学外の場所は OpenStreetMap の場所検索([Photon](https://photon.komoot.io/))の結果が続きます。候補から選んだ学外の場所は緯度経度も保存されます。
- **詳細ページ**: 学内の建物はキャンパスマップ(イラスト)にピンと建物名を表示し、あわせて Google マップを表示します。
  学外の場所は選んだ位置の Google マップを表示します(候補から選ばずに入力した場合は名称で検索)。オンライン開催では地図を出しません。
- **ピン位置の設定**: 学生課の管理画面「📍 キャンパスマップのピン設定」(`/admin/campus-map`)で、建物を選んでイラスト上をクリックすると位置を修正できます。
  初期位置は緯度経度からの概算で、位置が分からない建物は「未設定」です。
  画面で直した位置はそのパソコンのデータベースにだけ保存されます。チームで共有するには、アプリを止めて
  `flask apply-pins` を実行すると修正値が `campus_events/places.py` に書き戻されるので、それをコミットします。
- 学内の建物の一覧と緯度経度は `campus_events/places.py` の `CAMPUS_PLACES` で管理しています。
- 学外の場所検索の API は環境変数 `PLACE_SEARCH_URL` で変更できます(空にすると学内の建物のみ候補に出します)。
  Photon の公開サーバーは試用向けなので、本番運用では自前のサーバーか Google Places API などへの切り替えを検討してください。

### おすすめ・お気に入り・データ分析
- **おすすめの仕組み**: イベント名・内容・カテゴリの文章を文字単位の TF-IDF でベクトル化し、閲覧したイベント(閲覧した日数 × 重み 1、
  3 日分まで)とお気に入り(重み 5)に近いイベントをコサイン類似度で並べます。対象は公開中・開始前で、まだ見ていないイベントです。
  サイトで申込を受け付けていて満員のイベントは除きます。履歴がないときは閲覧・お気に入りの多い順に表示します。
- **ブラウザーの識別**: 署名付き Cookie のランダムな ID で識別し、氏名・メールアドレス・学籍番号とは結び付けません。
  学生課としてログイン中の閲覧は記録しません。
- **閲覧履歴の保存期間**: 90 日。古い履歴は自動で削除され、`flask purge-view-history` でも削除できます。
  学生は「おすすめ」画面から自分の閲覧履歴・お気に入りを削除できます。
- **デモ用データ**: `flask seed-ds-demo` で「【DSデモ】」の付いた架空のイベント・申込・閲覧を追加できます(実際の利用実績ではありません)。
- 処理は `recommendations.py`(おすすめ)、`behavior.py`(閲覧・お気に入りの記録)、`analytics.py`(集計)にあります。
  計算に scikit-learn / NumPy / SciPy を使います(`requirements-ds.txt`)。

## セットアップ

```bash
pip install -r requirements.txt
export FLASK_APP=campus_events
flask init-db
flask seed-db
flask run
```

- `flask init-db`: データベースを作成します(既存データは消えます)
- `flask seed-db`: (任意)動作確認用のサンプルイベントを投入します
- `flask run`: http://127.0.0.1:5000 で起動します
- `flask seed-ds-demo`: (任意)おすすめ・データ分析の確認用に、架空のデモイベントと閲覧データを追加します

### 学生課のログインと操作履歴
学生課の担当者が行った操作(承認・差し戻し・審査待ちに戻す・登録・編集・削除・参加申込の取消・ピン設定・ログイン)は、
「誰が・いつ・何を」の形で記録され、学生課の画面だけで見られます(学生向けの画面・API には出しません)。

| 表示場所 | 内容 |
| --- | --- |
| 管理画面トップ | 各イベントの「最終審査」(担当者名と操作) |
| 審査画面 | 最終審査の担当者と日時、そのイベントの操作履歴 |
| 操作履歴(`/admin/audit`) | 全操作の一覧(新しい順に 300 件)。削除したイベントも名前が残る |

ログイン方法は 2 通りです。

- **Google ログイン(推奨)**: `STAFF_EMAILS` に登録した職員のメールアドレスだけがログインでき、本人確認済みのアドレスで記録されます。
  学生のログインと同じ Google の設定(`GOOGLE_CLIENT_ID` / `GOOGLE_CLIENT_SECRET`)を使います。
  ```bash
  export STAFF_EMAILS='tanaka@example.ac.jp,suzuki@example.ac.jp'
  ```
- **共通パスワード**: `ADMIN_PASSWORD` を設定している間は使えます。ログイン時に「担当者名」の入力が必須で、
  履歴には「自己申告」と表示されます(本人確認はしない)。Google ログインに移行したら `ADMIN_PASSWORD` を空にして無効にできます。

### 学生のログイン(大学の Google アカウント)
ログインは任意です。設定しなければログインボタンは表示されず、これまでどおり使えます。

1. [Google Cloud Console](https://console.cloud.google.com/) でプロジェクトを作り、「API とサービス」→「OAuth 同意画面」を設定する
   (大学の Google Workspace 内だけで使うなら、ユーザーの種類は「内部」)
2. 「認証情報」→「認証情報を作成」→「OAuth クライアント ID」(種類: ウェブ アプリケーション)を作成し、
   承認済みのリダイレクト URI に `http://127.0.0.1:5000/login/google/callback` を追加する
   (公開する URL で使う場合は、その URL の `/login/google/callback` も追加)
3. 発行されたクライアント ID とシークレットを環境変数に設定して起動する

```bash
export GOOGLE_CLIENT_ID='xxxxx.apps.googleusercontent.com'
export GOOGLE_CLIENT_SECRET='xxxxx'
flask run
```

- ログインできるのは `@st.kitasato-u.ac.jp` のアカウントだけです(`ALLOWED_EMAIL_DOMAIN` で変更可)。
  メールアドレスの確認済み・大学の Google Workspace 管理のアカウントであることも確認します。
- 大学の Google 管理者が外部アプリでのログインを制限している場合は、情報システムの担当部署への確認が必要です。
- Google の設定なしで画面を確認したいときは `export ALLOW_DEV_LOGIN=1` で「開発用ログイン」が使えます
  (本人確認をしないため、人に公開するときは必ず無効にしてください)。
- 公開先の URL が Flask から正しく分からない環境(トンネル経由など)では、`GOOGLE_REDIRECT_URI` にコールバック URL を直接設定します。

ログインすると次のことができます。

| 機能 | 内容 |
| --- | --- |
| 端末をまたいだ記録 | お気に入り・閲覧履歴・参加申込をアカウント単位で保存。ログイン前にこのブラウザーで保存した分も引き継ぐ |
| マイページ(`/mypage`) | 自分の参加申込の一覧と取消(開始前まで)、ログイン中に応募したイベントの審査状況とコメント |
| 申込・応募の自動入力 | 参加申込はアカウントのメールアドレスで行い、氏名も自動で入る。応募フォームの連絡先も自動で入る |
| おすすめへの反映 | 申し込んだイベントを、閲覧(1)・お気に入り(5)より重い 8 の重みで好みの推定に使う |

学生課の管理画面パスワードは環境変数で設定してください(未設定時は開発用の `admin`)。

```bash
export ADMIN_PASSWORD='十分に長いパスワード'
export SECRET_KEY='ランダムな文字列'
```

データベース(SQLite)とアップロードされたポスター画像は `instance/` に保存されます。
アプリを更新したときは、起動時にデータベースの構成が自動で最新化されます(登録済みのデータは残ります)。

## 構成

```
campus_events/
  __init__.py     アプリ生成、CSRF 対策、テンプレート用フィルタ
  public.py       学生向け画面
  admin.py        学生課向け管理画面
  events.py       カテゴリ等の定数、入力検証、DB 操作、iCalendar 生成
  places.py       学内の建物の位置、学外の場所検索、地図表示
  recommendations.py  おすすめの計算
  behavior.py     閲覧履歴・お気に入りの記録
  analytics.py    データ分析の集計
  data_science.py おすすめ・お気に入り画面
  accounts.py     学生・学生課の Google ログインとマイページ
  audit.py        学生課の操作履歴
  db.py / schema.sql / schema_ds.sql / seed.py / seed_ds.py
  templates/ static/(おすすめ・分析用は ds/ 以下)
tests/
```
