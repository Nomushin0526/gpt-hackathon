================================================================================
1. アプリの目的と全体像
================================================================================

■ 目的
  (1) 紙のポスターでしか告知されておらず学生に知られていないイベントを、
      Web 上でまとめて見られるようにする。
  (2) 学生個人や部活動・サークルが企画したイベントを、学生課へ気軽に
      掲載申請できる窓口(プラットフォーム)をつくる。

■ 全体の流れ
  [学生・団体]                [学生課]                  [学生]
  イベントを応募 ──→ 審査待ち ──→ 承認して公開 ──→ 一覧・詳細で閲覧
        │                    └→ 差し戻し(コメント)       参加申込
        └─ 受付番号で審査状況を確認 ←─┘                  お気に入り・おすすめ

  学生課は、紙の掲示物などを自分で登録することもできる(審査なしで即公開)。

■ 技術構成
  ・言語 / フレームワーク : Python 3.11 以上 / Flask 3
  ・データベース           : SQLite(ファイル 1 つ。instance/campus_events.sqlite)
  ・画面                   : サーバー側で HTML を生成(Jinja2 テンプレート)
                             + 少量の JavaScript(static/app.js など)
  ・おすすめの計算         : scikit-learn / NumPy / SciPy
  ・外部サービス           : Google マップ(埋め込み表示。API キー不要)
                             Photon(OpenStreetMap ベースの場所検索)
  ・時刻                   : すべて日本時間(Asia/Tokyo)で扱う

2. 利用者と権限
================================================================================

  利用者        | ログイン         | できること
  --------------+------------------+---------------------------------------------
  学生(閲覧者)| 不要             | イベントの閲覧・検索、参加申込、お気に入り、
                |                  | おすすめの閲覧、カレンダー登録
  学生・団体    | 不要             | イベントの応募(掲載申請)、受付番号による
  (企画者)    |                  | 審査状況の確認
  学生課        | 共通パスワード   | 審査、イベントの登録・編集・削除、申込者管理、
                |                  | キャンパスマップのピン設定、データ分析

  ・学生のログイン機能はない。応募者は「受付番号」で、自分の応募を確認する。
  ・学生課は 1 つの共通パスワードでログインする(個人アカウントはない)。
  ・おすすめ・お気に入りは、ブラウザーごとに Cookie で区別する(第 7 章)。

4. 学生向けの機能
================================================================================

--------------------------------------------------------------------------------
4-1 イベント一覧(トップページ  /)
--------------------------------------------------------------------------------
■ 表示されるもの
  ・「公開中(承認済み)」のイベントだけ。審査待ち・差し戻しは表示しない。
  ・カード 1 枚に、開催日、バッジ、イベント名、日時、場所、主催者、
    定員・申込人数を表示する。

■ バッジの種類
  バッジ          | 表示の条件                                     | 見た目
  ----------------+------------------------------------------------+------------
  ✍ 要申込        | 参加方法が「このサイトで申込」か「外部で申込」 | オレンジ地・白文字
  満員            | このサイトで申込 かつ 申込人数 ≧ 定員          | 赤地・白文字
  申込不要        | 参加方法が「申込不要」                         | 灰色
  カテゴリ名      | 常に表示                                       | 灰色
  学生課掲載      | 学生課が登録したイベント                       | 青系
  学生企画        | 学生・団体の応募から公開したイベント           | ピンク系
  ★ お気に入り    | このブラウザーでお気に入りに保存済み           | (おすすめ機能)

■ 検索・絞り込み(すべて組み合わせ可能)
  ・キーワード : イベント名・内容・場所・主催者名に含まれるものを探す(部分一致)
  ・カテゴリ   : 9 種類から選択(第 8 章)
  ・主催者種別 : 5 種類から選択(第 8 章)
  ・期間       :
      これから開催   … 終了日時(無ければ開始日時)が今以降のもの
      1 週間以内     … 上の条件 かつ 開始日時が今から 7 日以内
      1 か月以内     … 上の条件 かつ 開始日時が今から 31 日以内
      終了したイベント … 終了日時(無ければ開始日時)が今より前のもの
  ・並び順 : 「終了したイベント」は開始日時の新しい順、それ以外は近い順。

■ おすすめ欄
  検索条件を何も指定していない通常のトップページ(期間「これから開催」)の
  ときだけ、上部におすすめを 3 件表示する。表示できるおすすめが無ければ出さない。

--------------------------------------------------------------------------------
4-2 イベント詳細(/events/<id>)
--------------------------------------------------------------------------------
  ・公開中のイベントだけ表示する。審査待ち・差し戻し・存在しない ID は
    「ページが見つかりません」(404)。
  ・表示項目 : バッジ、イベント名、日時、場所、主催(名称と種別)、参加方法、
    定員、問い合わせ先メール、内容、ポスター画像、地図(第 6 章)。
  ・「☆ お気に入りに保存」/「★ お気に入りを解除」ボタン(第 7 章)。
  ・ページ下部に「参加申込」欄。参加方法によって内容が変わる。
      申込不要       … 「申込は不要です」と表示
      外部で申込     … 申込方法・申込先(URL など)を表示
      このサイトで申込 … 申込人数と申込フォーム(4-3)
  ・学生課としてログイン中は「管理画面で開く」リンクが出る。
  ・学生課としてログインしていない人がこのページを開くと、閲覧履歴が
    1 件記録される(第 7 章)。

--------------------------------------------------------------------------------
4-3 参加申込(このサイトで受け付ける場合)
--------------------------------------------------------------------------------
■ 入力項目
  氏名(必須・50 文字以内)、学籍番号(任意・20 文字以内)、
  メールアドレス(必須・200 文字以内)

■ 申込を受け付ける条件(すべて満たすとき)
  ・イベントが公開中
  ・参加方法が「このサイトで参加申込を受け付ける」
  ・開始日時より前(開始後は「申込受付は終了しました」)
  ・定員に空きがある(定員が空欄なら人数制限なし)

■ 処理の流れ
  1. 入力をチェックする(第 8 章)。メールアドレスは小文字にそろえて保存する。
  2. 「定員に空きがあるか」の確認と登録を、データベースへの 1 回の命令で
     同時に行う。複数人が同時に申し込んでも定員を超えない。
  3. 同じイベントに同じメールアドレスで申し込むと
     「このメールアドレスはすでに申込済みです」とエラーにする
     (データベースの一意制約でも防いでいる)。
  4. 定員に達していれば「定員に達したため申込を締め切りました」とエラーにする。
  5. 成功すると詳細ページに戻り「参加申込を受け付けました」と表示する。

■ 補足
  ・申込者の氏名・メールアドレス・学籍番号は公開されない(学生課のみ閲覧可)。
  ・申込者本人による取消の機能はない。取消は学生課が行う(5-6)。
  ・申込完了のメール通知はない。

--------------------------------------------------------------------------------
4-4 申込人数のリアルタイム表示
--------------------------------------------------------------------------------
  ・一覧・詳細ページに「申込 ○ 名 / 定員 ○ 名  残り ○ 名」と残量バーを表示。
  ・バーの色 : 通常は緑、残り 2 割未満(80% 以上埋まった)でオレンジ、満員で赤。
  ・ページを開いている間、10 秒ごとに最新の人数を取得して表示を更新する。
    ページを再読み込みしなくても、他の人の申込が反映される。
  ・ブラウザーのタブが裏に回っている間は更新を止め、表に戻った時点で更新する。
  ・閲覧中に満員になると、バッジが「満員」に変わり、申込フォームが
    「定員に達したため、申込を締め切りました」に置き換わる。
  ・人数は /api/registration-counts から取得する(1 回に 100 件まで。
    公開中のイベントのみ。個人情報は含まない)。

--------------------------------------------------------------------------------
4-5 カレンダーに追加(.ics)
--------------------------------------------------------------------------------
  ・詳細ページの「📅 カレンダーに追加(.ics)」で、iPhone・Android・Google
    カレンダー・Outlook などに取り込めるファイルをダウンロードできる。
  ・イベント名、日時、場所、内容が入る。終了日時が無い場合は開始から 1 時間とする。
  ・公開中のイベントのみ。

--------------------------------------------------------------------------------
4-6 イベントの応募(学生・団体 → 学生課  /submit)
--------------------------------------------------------------------------------
■ 入力項目(詳細は第 8 章)
  イベントの内容 : イベント名、カテゴリ、内容、開始・終了日時、開催場所
  参加方法       : 申込不要 / このサイトで申込 / 外部で申込、定員、申込方法・申込先
  主催者         : 主催者・団体名、主催者の種別、連絡先メールアドレス(必須)
  ポスター画像   : 任意(PNG / JPEG / GIF / WebP、5MB まで)
  学生課への連絡 : 連絡事項(公開されない。学籍番号・代表者名・施設使用の予定など)
  同意           : 「掲載内容に誤りがなく、学内の規則に従って実施する」への同意(必須)

■ 処理の流れ
  1. 入力をチェックする。誤りがあれば、入力内容を残したままエラーを表示する。
  2. ポスター画像があれば、ランダムなファイル名に変えて保存する(第 11 章)。
  3. ステータス「審査待ち」、種別「学生企画」で登録する。
  4. 8 文字の受付番号を発行し、完了画面に表示する。
     受付番号は読み間違えやすい文字(0・O・1・I・L)を使わない英数字。
  5. 応募者は受付番号を控えておく(スクリーンショットなど)。
     受付番号を紛失した場合に再確認する機能はない。

■ 注意書き(画面に表示)
  教室・施設の使用許可が必要な場合は、別途学生課で所定の手続きを行うこと。
  (この応募は「掲載の申請」であり、施設の使用申請を兼ねない。)

--------------------------------------------------------------------------------
4-7 審査状況の確認(/status)
--------------------------------------------------------------------------------
  ・受付番号を入力すると、イベント名、開催日時、ステータスを表示する。
    大文字・小文字は区別しない。
      審査待ち … 「学生課で内容を確認しています」
      公開中   … 公開ページへのリンク
      差し戻し … 「修正のうえ再度応募してください」
  ・学生課からのコメントがあれば表示する。
  ・差し戻された応募を応募者が直接修正する機能はない。新しく応募し直す。


================================================================================
5. 学生課向けの機能(管理画面)
================================================================================

--------------------------------------------------------------------------------
5-1 ログイン・ログアウト
--------------------------------------------------------------------------------
  ・/admin/login で共通パスワードを入力する。画面下部の「学生課の方はこちら」から
    開ける。
  ・パスワードは環境変数 ADMIN_PASSWORD で設定する。未設定のときは開発用の
    「admin」になるため、人に使ってもらう前に必ず設定すること。
  ・ログイン状態はブラウザーのセッション(署名付き Cookie)で保持する。
  ・ログアウトは上部メニューの「ログアウト」。
  ・ログイン前に管理画面の URL を開くと、ログイン後にその画面へ戻る
    (管理画面内の URL に限る。外部サイトへは移動しない)。

--------------------------------------------------------------------------------
5-2 管理画面トップ(/admin/)
--------------------------------------------------------------------------------
  ・「審査待ち」「公開中」「差し戻し」のタブと、それぞれの件数を表示する。
  ・一覧の列 : 開催日時、イベント名、主催、種別(学生課掲載 / 学生企画)、
    申込数(このサイトで申込の場合「申込数 / 定員」)、受付日。
  ・並び順 : 審査待ちは受付の古い順(先に来たものから処理できるように)、
    公開中・差し戻しは開催日時の新しい順。
  ・上部のボタン : 「イベントのデータ分析」「📍 キャンパスマップのピン設定」
    「＋ イベントを登録」。

--------------------------------------------------------------------------------
5-3 審査(/admin/events/<id>)
--------------------------------------------------------------------------------
  ・応募内容をすべて表示する。公開されない情報(受付番号、連絡先、
    応募者からの連絡事項)もここで確認できる。
  ・「応募者へのコメント」を書いて、次のいずれかを押す。
      承認して公開   … 一覧に公開される
      差し戻す       … コメントの入力が必須。応募者は受付番号でコメントを確認する
      審査待ちに戻す … 公開を取り下げて審査待ちにする
  ・コメントは応募者の「審査状況」画面に表示される。
  ・承認・差し戻しの結果を応募者にメールで知らせる機能はない。

--------------------------------------------------------------------------------
5-4 イベントの登録(紙掲示物の転載など  /admin/events/new)
--------------------------------------------------------------------------------
  ・学生課が直接イベントを登録する。審査なしで即時公開され、
    種別は「学生課掲載」になる。
  ・入力項目は応募フォームとほぼ同じ。違いは次のとおり。
      連絡先メールアドレス … 任意
      同意チェック、学生課への連絡事項 … なし
      主催者の種別 … 初期値が「学生課・大学」
  ・紙のポスターは写真を撮ってアップロードすると、スマートフォンからも見られる。

--------------------------------------------------------------------------------
5-5 イベントの編集・削除
--------------------------------------------------------------------------------
  ・編集(/admin/events/<id>/edit)
      すべての項目を変更できる。ステータスは変わらない。
      新しいポスターをアップロードすると、古い画像ファイルは削除される。
      「現在のポスターを削除」にチェックすると、画像を外せる。
  ・削除(確認ダイアログあり)
      イベント、そのポスター画像、参加申込、閲覧履歴、お気に入りをまとめて削除する。
      元に戻せない。

--------------------------------------------------------------------------------
5-6 参加申込者の管理
--------------------------------------------------------------------------------
  ・審査画面に「参加申込者(○ 名 / 定員 ○ 名)」の一覧を表示する。
      列 : No.、氏名、学籍番号、メールアドレス、申込日時
  ・「CSV ダウンロード」で一覧を保存できる。Excel で文字化けしないよう
    BOM 付き UTF-8 で出力する。
  ・各行の「取消」で申込を取り消せる(確認ダイアログあり)。
    取り消すと空きが 1 つ増え、一覧の人数表示にも反映される。


================================================================================
6. 開催場所と地図
================================================================================

--------------------------------------------------------------------------------
6-1 開催場所の入力候補
--------------------------------------------------------------------------------
  ・応募フォーム・登録フォームの「開催場所」に文字を入れると、
    0.3 秒ほど待ってから候補を表示する。
  ・候補の並び
      1. 学内の建物 … 入力した文字を名称に含む建物(全角・半角、括弧書き、
                      空白の違いは無視して比較する)
      2. 学外の場所 … 2 文字以上入力したときだけ、場所検索サービス Photon
                      (OpenStreetMap)で検索する。日本国内の結果のみ、最大 10 件。
                      キャンパスに近い場所が上に来る。学内の建物と同じ名前は除く。

--------------------------------------------------------------------------------
7-1 閲覧履歴の記録とブラウザーの識別
--------------------------------------------------------------------------------
■ ブラウザーの識別
  ・イベント詳細ページ・おすすめ画面・お気に入り画面を初めて開いたとき、または
    お気に入りに保存したときに、ランダムな ID(48 桁の英数字)を発行し、
    署名付き Cookie「campus_events_visitor」に保存する。
    (学生課としてログイン中に詳細ページを開いた場合は発行しない)
  ・Cookie は 180 日間有効。JavaScript からは読めない設定(HttpOnly)で、
    他サイトからの送信も制限している(SameSite=Lax)。
  ・署名が合わない(改ざんされた)Cookie は無視する。
  ・ID は氏名・メールアドレス・学籍番号とは結び付けない。
  ・ブラウザーや端末が違えば別人として扱う(履歴は共有されない)。

■ 閲覧の記録
  ・イベント詳細ページを開いたときに記録する。
  ・同じブラウザーが同じイベントを同じ日に何度開いても 1 件
    (最初と最後に開いた時刻だけ更新)。日が変われば別の記録。
  ・学生課としてログイン中の閲覧は記録しない。
  ・公開中のイベントだけ記録する。
  ・保存期間は今日を含めて 90 日。古い記録は、詳細ページ・おすすめ・
    データ分析を開いたときに自動で削除される。flask purge-view-history でも削除できる。

■ 学生自身による削除(おすすめ画面の「おすすめに使うデータと設定」)
  ・「閲覧履歴を削除」   … このブラウザーの閲覧履歴を削除。お気に入りは残る。
  ・「履歴とお気に入りを削除」… 両方を削除し、ブラウザーの ID も新しくする。
  ・Cookie を消しただけではサーバー上の記録はすぐには消えない(画面に注記あり)。

7-2 お気に入り(/favorites)
--------------------------------------------------------------------------------
  ・詳細ページやおすすめ画面の「☆ お気に入りに保存」で保存、「★ … 解除」で解除。
  ・お気に入り一覧に、保存したイベントを開催日の新しい順で表示する。
  ・保存済みのイベントは、一覧のカードに「★ お気に入り」と表示される。
  ・公開中のイベントだけ保存できる。非公開になったイベントは一覧に出ない。
  ・お気に入りは、おすすめの計算に強く反映される(7-3)。

--------------------------------------------------------------------------------
7-3 おすすめ(推薦)の計算方法(/recommendations、トップページの 3 件)
--------------------------------------------------------------------------------
■ 対象
  ・おすすめに出す候補 : 公開中で、まだ始まっていないイベント。
    ただし、このブラウザーで閲覧済み・お気に入り済みのものは除く(新しい発見のため)。
    「このサイトで申込」で満員のものも除く。
  ・好みの推定に使う履歴 : 過去 90 日の閲覧と、現在のお気に入り。
    開催済みのイベントの閲覧も好みの推定には使う。

■ 計算の手順(内容が近いものを探す)
  1. 公開中の各イベントについて「イベント名(2 回)+ 内容 + カテゴリ」の文章を作る。
     イベント名を 2 回入れることで、名前の一致を重視する。
  2. 全角・半角や大文字・小文字をそろえ、2〜4 文字ずつ区切った断片
     (日本語でも単語分割が不要な方法)の出現の特徴を TF-IDF という方法で
     数値の並び(ベクトル)にする。
     TF-IDF : そのイベントによく出て、他のイベントにはあまり出ない言葉ほど
              重く扱う方法。
  3. このブラウザーの「好み」を、履歴のイベントのベクトルの重み付き合計で作る。
       閲覧 : 閲覧した日数 × 1(同じイベントは 3 日分まで)
       お気に入り : 5
  4. 好みと各候補の近さをコサイン類似度(0〜1。1 に近いほど似ている)で計算し、
     近い順に並べる。類似度が 0 のものは出さない。
  5. 各候補に「おすすめの理由」と類似度を表示する。類似度は確率ではない。

■ 履歴が無い・近いものが無いとき(人気順)
  ・初めての人、または内容の近い候補が無い場合は、人気順で表示する。
      人気度 = お気に入り数 × 5 + 閲覧(ブラウザーごとに 3 日分まで)× 1
               + このサイトでの申込数
  ・利用実績が全く無いイベントは、開催日時の近い順。
  ・理由欄に「履歴がないため」などの根拠を表示する。

■ 表示件数
  トップページ 3 件、おすすめ画面 12 件まで。

--------------------------------------------------------------------------------
7-4 データ分析(学生課  /admin/analytics)
--------------------------------------------------------------------------------
■ 期間の指定
  ・イベントの「開催開始日」で絞り込む。初期値は「今日の 90 日前 〜 30 日後」。
  ・対象は公開中のイベントのみ。
  ・その期間に開催されるイベントについて、申込・お気に入りは「現在残っている
    すべて」、閲覧は「保存期間(90 日)内のすべて」を数える
    (申込日・閲覧日では絞らない)。

■ 表示する指標
  ・公開イベント数(うちサイト内受付の数)
  ・サイト内申込の合計、1 イベントあたりの平均申込
    (このサイトで申込のイベントだけで計算。外部・申込不要は人数が分からないため
     「0 件」とは扱わず「対象なし / ―」と表示)
  ・定員充足率 = 申込の合計 ÷ 定員の合計 × 100
    (定員が分かる「このサイトで申込」のイベントだけ。各イベントの率の単純平均ではない)
  ・閲覧記録数、閲覧したブラウザー数、現在のお気に入り数
    (ブラウザー数は実際の人数ではない)
  ・カテゴリ別の傾向(申込件数 / 1 イベント平均 を切り替え)
  ・開催曜日別の傾向(月〜日)
  ・サイト内申込の多いイベント 上位 10 件
  ・イベント別の集計表(申込、定員、充足率、閲覧、お気に入り)
  ・「数値の読み方」の注意書き

■ 出力
  ・「CSV を保存」: イベント別の集計を CSV で保存(BOM 付き UTF-8)。
    セルの先頭が = + - @ の場合は先頭に ' を付け、Excel で式として
    実行されないようにしている。
  ・/admin/analytics.json : 同じ内容の JSON。
  ・どちらも個人情報(氏名・メールアドレス等)は含まない。

11. セキュリティと個人情報の取り扱い
================================================================================

■ 不正な送信の防止
  ・すべてのフォーム送信に、ページごとのランダムな確認用の値(CSRF トークン)を
    付けている。値が合わない送信は拒否する(他サイトからの成りすまし送信対策)。
  ・データベースへの命令は、入力値を直接文字列に埋め込まない方式
    (プレースホルダー)で書いている(SQL インジェクション対策)。
  ・画面に表示する値は自動でエスケープしている(スクリプト埋め込み対策)。

■ ログイン
  ・パスワードの比較は、処理時間から推測されにくい方法で行う。
  ・ログイン後の移動先は管理画面内に限定する。

■ ファイルのアップロード
  ・拡張子が png / jpg / jpeg / gif / webp 以外は拒否する。
  ・保存時のファイル名はランダムな名前に変える(元のファイル名は使わない)。
  ・5MB まで。

■ 個人情報
  情報                      | 公開範囲
  --------------------------+-------------------------------------------
  参加申込者の氏名・メール・| 学生課のみ(審査画面・CSV)
  学籍番号                  |
  応募者の連絡事項          | 学生課のみ
  受付番号                  | 応募者本人と学生課
  主催者の連絡先メール      | 詳細ページで公開(問い合わせ先として)
  閲覧履歴・お気に入り      | 個人と結び付けない。学生課の分析でも
                            | 件数としてのみ表示
  ・データ分析の画面・CSV・JSON には個人情報を含めない。
  ・トップページ・詳細ページ・おすすめ・お気に入り・データ分析は、閲覧者ごとに
    内容が変わるため、ブラウザーやプロキシにキャッシュさせない設定。

■ 外部サービスに送られる情報
  ・Google マップ : 開催場所の名称または緯度・経度(詳細ページを開いた人の
    ブラウザーから Google へ)。
  ・Photon : 開催場所の入力欄に入れた文字(サーバーから Photon へ)。

16. 既知の制約・注意点・今後の課題
================================================================================

■ 運用前に必ず行うこと
  ・ADMIN_PASSWORD と SECRET_KEY を設定する。
  ・flask run は開発用のサーバー。常時公開する場合は本番用の仕組み
    (Gunicorn など)とサーバーへの配置が必要。

■ 機能上の制約
  ・学生のログインが無い。応募者は受付番号を紛失すると確認できない。
  ・差し戻された応募を応募者が修正・再申請する機能が無い(新しく応募し直す)。
  ・参加申込者が自分で取り消す機能が無い(学生課が取り消す)。
  ・メール通知(応募受付、審査結果、申込完了)が無い。
  ・学生課のアカウントは共通パスワード 1 つ。誰が操作したかは記録されない。
  ・審査待ちのイベントのポスター画像も、画像の URL を知っていれば開ける
    (URL はランダムなので推測はできない)。
  ・おすすめ・お気に入りはブラウザー単位。端末を変えると引き継がれない。
  ・データ分析の閲覧数・ブラウザー数は実際の人数ではない。
  ・SQLite は 1 ファイルのデータベース。大人数の同時利用には向かない。

■ 確認が必要な事項
  ・キャンパスマップのイラスト(campus_map.webp)は大学公式の地図と思われる。
    リポジトリが公開(Public)なので、掲載してよいか確認すること。
  ・建物名のうち、V号館の所在、「クレセント」の正式名称、「学生課」という部署名は
    実物で確認すること。
  ・ピン未設定の建物 7 件の位置を、管理画面から設定すること。
  ・Photon の公開サーバーは試用向け。本番では自前のサーバーや Google Places API
    などへの切り替えを検討すること。
  ・閲覧履歴を Cookie で 90 日記録すること(個人は特定しない)を、発表や
    利用案内で説明しておくとよい。

■ 検討中(未実装)の機能
  ・ポスター画像の読み取りによる入力欄の自動入力(学生課のみ。ポスターに無い
    項目は空欄のまま)。ChatGPT の API を使えるか(ChatGPT Edu のクレジットが
    API に使えるか)を主催者に確認中。
  ・イベント企画の相談チャットボット(規程に基づく案内、許可判断はしない、
    学生課への引き継ぎ)。学生課からの資料提供が前提。カスタム GPT で作る案もある。
  ・大学アカウント(SSO)でのログイン、カレンダー表示、リマインダー、
    施設使用申請との連携。
